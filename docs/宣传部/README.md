## 2. 宣传部日常改什么（★ 先看这张表）

| 我想改… | 改哪个文件 | 说明 |
|---|---|---|
| 公众号 / B 站 / 抖音关注链接 | `src/config.ts` §一、§二（`LINK_*`） | 直接改 URL 字符串 |
| 报名二维码、招新群二维码 | `src/config.ts` §四 | 图片放 `public/images/招新/`，路径写在 config |
| 首页轮播图（17 张） | 图片放 `public/images/首页/首页1.jpg…17.jpg` | 顺序与 `IMG_首页轮播` 一一对应；换图直接覆盖同名文件 |
| 部门介绍图 / 部门推文链接 | `src/config.ts`（`IMG_*` / `LINK_*`） | 图片放 `public/images/部门/` |
| 暑期实践图集（玉树/秦川/秦岭/萤火/启明星/陕博/银发融城） | `public/images/暑期实践/<组名>/` | 命名见 `docs/SUMMER-GALLERY-SLOTS.md`；已有组名按数字续号 |
| 荣誉墙（27 项） | `public/images/荣誉/荣誉1.jpg…27.jpg` + `src/content.ts` | 图片覆盖同名；文案/奖项名改 `content.ts` |
| 任何介绍文案、部门介绍、FAQ 条目 | `src/content.ts` | **改字只改这里**，不要动组件 |
| 页面背景、活动剪影 | `public/images/页面背景/`、`public/images/公益剪影/` | 命名见 `docs/IMAGE-NAMING-PLAN-CN.md` |
| 组织架构图 / 治理架构图 | 图片生成脚本见 §4；直接覆盖 `public/images/架构图/` | 治理架构图当前只用在 README，网页不引用 |
| 问卷 / 表单 / 报名链接更新 | `src/config.ts` §一 | 换链接后记得同步 README 与公众号 |

> **一句话原则**：**图片 = 丢进 `public/images/` 覆盖同名文件；文字 = 改 `src/content.ts`；链接 = 改 `src/config.ts`。** 组件代码（`src/components/`）除非布局大改，否则不动。

## 3. 改图规范（宣传部最重要的一课）

1. **命名即生效**：先查 `docs/IMAGE-NAMING-PLAN-CN.md` 的表，用表里的中文文件名放到对应目录；**不要新建英文目录，不要改组件里的路径**。
2. **图片尺寸建议**：
   - 首页轮播 / 暑期图集：横图 16:9，单张 ≤ 1.5MB（JPG）
   - 部门封面：与现有同目录图片同比例
   - 二维码 / 吉祥物 / 图标：PNG（透明底）
   - 长图（如治理架构图）：竖版 2:3 左右，压缩后几百 KB 最佳（**当前治理架构图 1024×1536 PNG ~2.5MB，尚未压缩，待处理**）
3. **隐私红线**：涉及萤火、医院、特殊儿童、特殊群体的照片，**必须先遮挡可识别脸部**；不发布未经授权的人脸特写。
4. **引用数字前先查事实**：所有对外数字（199 人、44 位负责人、17 届玉树、42 项活动、1600+ 小时等）必须在 `docs/PUBLIC-FACT-REGISTER.md` 找到锚点；**答不上来的数字宁可不说**。
5. **上传前自检**（在仓库根目录）：

```bash
npm run validate:assets   # 校验 config 里引用的图片/视频是否都存在
npm run audit:public      # 对外信息面审计（防止内部内容泄漏）
npm run typecheck         # TypeScript 语法检查
```

## 4. 架构图怎么重新生成（如果以后要改人员/部门）

```bash
npm run org-chart     # 重建 组织架构图.png（44 人，数据在 scripts/org-chart-data.mjs）
```

- 人员姓名 / 职务 / 关键词标签**全部在** `scripts/org-chart-data.mjs`，改这里再跑脚本即可。
- **治理架构图**（`public/images/架构图/治理架构图.png`）目前是 AI 生图 + 手动校字后的成品图，**没有稳定再生成脚本**（旧的 `build-gov-chart.mjs` 已删除，避免覆盖成品）。改它 = 换图 → 校验文字 → 自检。

## 5. 本地预览 & 发布流程

### 第一次跑

```bash
npm install          # 安装依赖（只需一次）
npm run dev          # 开发服务器，改完自动热更新，浏览器打开终端里的地址
```

### 常用命令

```bash
npm run dev            # 本地开发预览
npm run build          # 生产构建 → dist/
npm run preview        # 预览构建产物
npm run typecheck      # TS 检查
npm run validate:assets
npm run audit:public
```

### 发布（上线）

1. 改完 → 本地自检通过。
2. 在仓库根目录：

```bash
git add -A
git commit -m "feat: 宣传部 更新 XX（简述改了什么）"
git push origin main
```

3. Cloudflare Pages 会自动构建部署，约 1 分钟后访问 <https://yzaxs-1.pages.dev> 验证。

> **纪律**：每完成一个小改动就提交，**绝不攒一堆提交**；不要动 `main` 以外的分支历史（除非你明确知道在做什么）。
