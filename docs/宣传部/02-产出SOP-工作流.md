# 宣传部 · 产出 SOP（工作流）

> **最后更新**：2026-09-04　**作者**：Claude + 孙承泽
>
> 适用对象：宣传部全体（4 部长 + 25-26 干事 + 9 个月后达标的「独立接活」同学）。
> 这份 SOP 管所有「产出」——推送、视频、海报、横幅、直播，一条都不漏。

---

## 0. 先说在前头

宣传部的产出 = 整个社团的「门面」。一份糟糕的推文、一个错字的横幅、一段 5 秒黑屏的视频，**都会让其他部门甚至校外的同学重新评价英仔爱心社**。

所以我们的工作流不是"几个部长随手安排一下"，而是**每个步骤都有明确的人、明确的截止时间、明确的 Review 规则**。

> **我们不追求快，但追求稳**。一次没接活的下场，比两次没接活的下场更糟——因为其他部门会去找别人做。

---

## 1. 5 步流程总览

```
[ 1. 接活登记 ] → [ 2. 方案过审 ] → [ 3. 制作 ] → [ 4. 发布前 Review ] → [ 5. 发布 + 归档 ]
       ↓                ↓                ↓                ↓                     ↓
  哪个部门提的？    部长会议≤24h    干事主笔          4 部长中≥2 确认       原文件 + 复盘
  截止日？          通过才进下一步   部长 Review      不通过 → 回 3 重做      归档到对应目录
  形式？                              中间稿
  主负责人？
  Reviewer？
```

> **关键原则**：每一步都有**明确的产出物**（不是"我们想了一下"），没产出物 = 没做。

---

## 2. 5 步流程详解

### 2.1 第 1 步：接活登记（群公告 / 表单）

**谁**：当月轮值 Reviewer 部长（见 §5）+ 接到需求的干事。

**时机**：收到需求后 **30 分钟内**完成登记。

**产出物**：一份「接活登记单」（模板见 §3）。

**登记渠道**（二选一）：
- **部门预热群**公告（简单需求，例：换一张首页轮播图）。
- **金数据 / 问卷星表单**（复杂需求，例：一次完整活动的全套宣传）。

**不登记 = 没接活**。即使部长口头上答应了，也必须补登记。

---

### 2.2 第 2 步：方案过审（部长会议 ≤ 24 小时）

**谁**：4 位部长集体审。

**时机**：登记后**24 小时内**开一次短会（线上 / 线下均可），**给出"通过 / 修改后通过 / 不通过"**决定。

**产出物**：方案文档（哪怕是 1 页纸也必须写）。

**方案文档必含**：
- 活动 / 需求背景（1 段话）。
- 产出形式（推送 / 视频 / 海报 / 横幅 / 直播 / 多件套）。
- 主负责人（必须是 1 个具体的人，不写"宣传部"）。
- Reviewer（轮值部长）。
- 截止时间（精确到日 / 时）。
- 风险点（如有）：拍照无人 / 嘉宾临时改时间 / 服务器问题等。

**三种结果**：
| 结果 | 含义 |
|---|---|
| 通过 | 进入第 3 步制作 |
| 修改后通过 | 主负责人改完再发到群里"@全体部长 二次确认"，3 人同意 → 进入制作 |
| 不通过 | 写 1 段不通过理由（例：与社团风格不符 / 时间不可行），回到第 1 步重做 |

> **不通过不是批评**，是"这个方案我们不接"。保护部门声誉比"接到活"更重要。

---

### 2.3 第 3 步：制作（干事主笔 + 部长 Review 中间稿）

**谁**：主负责人（干事）主笔，Reviewer 部长 Review 中间稿。

**时机**：方案通过后立刻开工，截止前 **48 小时**交中间稿给 Reviewer。

**中间稿必含**：
- 推送：秀米预览链接 + 1 张截图。
- 视频：1 段 30-60 秒粗剪 + 完整脚本。
- 海报 / 横幅：PSD / Canva 源文件 + 1 张 PNG 预览。
- 直播：流程表 + 嘉宾名单 + 测试推流链接。

**Reviewer 反馈**：
- 收到中间稿后 **24 小时内**给反馈（通过 / 改 A 处 / 改 B 处 / 改 C 处）。
- 反馈用**腾讯文档批注**，不留口头反馈。
- 反馈不超过 3 轮，**第 3 轮必须通过**（不然就是中间稿本身有问题，不是改的问题）。

---

### 2.4 第 4 步：发布前 Review（4 部长中 ≥ 2 部长确认）

**谁**：4 部长投票。

**时机**：最终稿定稿后**截止时间前 24 小时**（如果是当天发布，至少提前 6 小时）。

**Review 必查**：
- [ ] 文字无错字（特别是领导人姓名 / 单位名称）。
- [ ] 数字与 `docs/PUBLIC-FACT-REGISTER.md` 一致。
- [ ] 图片无未授权人脸（萤火 / 医院 / 特殊儿童 / 特殊群体）。
- [ ] 二维码 / 链接有效（已扫过）。
- [ ] 风格与社团调性一致（不浮夸 / 不油腻 / 不 AI 套话）。
- [ ] 涉及校外发布的，已通过校团委 / 指导老师审核。

**通过条件**：4 部长中至少 **2 人**在群里发"通过"。

**不通过**：
- 退回第 3 步重做。
- 紧急情况下，Reviewer 部长可"一票通过"+ 写"事后追认"（招新季 / 大活动 24 小时紧急制启用，见 §6）。

---

### 2.5 第 5 步：发布 + 归档（原文件 + 复盘）

**发布**：
- 主负责人在截止时间前**亲自发布**，不在截止后才发。
- 发布后 30 分钟内**自检**：链接有效 / 配图正常 / 阅读量爬升。
- 发布后 1 小时内，把发布链接 + 数据截图发到部门预热群。

**归档**（**重要**，未来所有工作的"地基"）：
- 原文件（PSD / 源视频 / 文档）→ `docs/宣传部/产出归档/<年月>-<活动名>/<形式>/`（**当前不存在，第一次发布后由部长创建**）。
- 复盘文档（200-500 字）→ 同目录下 `复盘.md`，包含：用了多久 / 哪里卡住 / 哪个环节浪费了时间 / 下次怎么改。

## 4. Reviewer 轮值表（4 部长按月轮值）

| 月份 | 轮值 Reviewer | 重点关注 |
|---|---|---|
| 2026-09 | 部长 A | 招新季高峰 |
| 2026-10 | 部长 B | 培训期 + 活动密集 |
| 2026-11 | 部长 C | 年中总结 |
| 2026-12 | 部长 D | 期末 + 寒假过渡 |
| 2027-01 | 部长 A | 寒假不值班 |
| 2027-02 | 部长 B | 寒假不值班 |
| 2027-03 | 部长 C | 培训 + 春季活动 |
| 2027-04 | 部长 D | 培训 + 雷锋月 |
| 2027-05 | 部长 A | 换届准备 |
| 2027-06 | 部长 B | 换届 + 暑假交接 |

> **轮值 Reviewer 的核心职责**：
> 1. 24 小时内响应接活登记。
> 2. 主持方案过审会议。
> 3. 中间稿 Review 不超过 3 轮。
> 4. 紧急情况下"一票通过"+ 事后追认。

> **轮值不等于独占**：其他部长依然可以主动 Review，只是主责归轮值。

## 5. 紧急接活通道（招新季 / 大活动 24 小时紧急制）

### 5.1 什么时候启用

- 招新季（7-9 月）。
- 大型活动当天 / 前 1 天。
- 其他部门明确表示"今天 / 明天就要"。

### 5.2 怎么启用

- 轮值 Reviewer 部长在群里发"紧急接活" + 标红。
- 跳过中间稿 Review 环节。
- 改用「双人 Reviewer 同步审」：轮值部长 + 1 位在线部长，**2 人都发"通过"即可发布**。

### 5.3 24 小时紧急制的"事后追认"

- 发布后 24 小时内，**必须**把发布物发到全部长群，做"事后追认"。
- 其他 2 位部长有 24 小时"异议期"，可要求撤稿 / 致歉 / 重做。
- 异议期过后，默认全员认可。

> **这条不是"开绿灯"**，是"承认紧急情况下我们不完美，但事后补上"。**永远不要悄悄发布**。

## 6. 失败案例库（翻车记录）

> **翻车不丢人，藏起来才丢人。** 每次翻车后 3 天内必须归档。

### 6.1 归档位置

`docs/宣传部/翻车记录/<年月>-<主题>.md`（**当前不存在，第一次翻车后由部长创建**）。

### 6.2 必须归档的"翻车"

- 文字错字（特别是校领导姓名 / 数字）。
- 图片用了未授权人脸。
- 链接 / 二维码失效。
- 截止时间后才发布。
- 被需求方 / 校方 / 团委驳回。
- 部长会议被否决 ≥ 2 次的方案。
- 任何登上校级 / 校外争议榜单的内容（即使我们不知情）。

### 6.3 翻车记录模板

```
# 翻车记录 / <年月>-<主题>

## 翻车经过（时间 / 涉及人 / 影响范围）
- 1 段话，**不替自己辩护**。

## 当时为什么翻车（深挖根因）
- 流程哪一步漏了？
- 是 Reviewer 没看到？还是主负责人没交？还是中间稿不审就发了？

## 补救措施
- 当下怎么救的？
- 后续致歉 / 重做的成本？

## 下次怎么避免（最关键的一段）
- 流程上要改什么？
- 培训要不要补一节？
- Reviewer 规则要不要调？
```

## 7. 优秀案例库

> 不是"为了鼓励"，是"把好做法沉淀下来"，下次直接抄。

### 7.1 归档位置

`docs/宣传部/优秀案例/<年月>-<主题>.md`（**当前不存在，第一次获奖 / 爆款后由部长创建**）。

### 7.2 必须归档的"优秀"

- 阅读量 / 完播率 **超过部门月均 3 倍** 的内容。
- 收到其他部门 / 校方 / 校外表扬的内容。
- 培训作业评分 ≥ 9/10 的产出。
- 部长会议评议"值得复盘"的方案。

### 7.3 优秀案例模板

```
# 优秀案例 / <年月>-<主题>

## 内容简介（1 段话）
- 形式 / 主题 / 实际效果（数据 + 反馈）。

## 哪几步做对了
- 接活：为什么接得到？
- 方案：为什么过审顺利？
- 制作：哪个环节最高效？
- Review：哪个 Reviewer 提的建议最关键？
- 发布：为什么效果好？

## 可复用的部分（直接抄）
- 排版模板 / 视频脚本结构 / 海报元素 / 配图文案。

## 主负责人 / Reviewer
- 名字 + 一句话评语（公示用）。
```

## 8. 与招新站的交接（重大活动 / 招新季同步更新网站内容）

> 招新站（`Yingzai2026` 仓库 → `yzaxs-1.pages.dev`）是英仔爱心社的"对外门面"，**宣传部做的活动如果有对外价值，必须同步上招新站**。

### 8.1 必须同步的"重大活动"

- 招新季活动（7-9 月）：招新推文、招新海报、招新横幅、招新直播（招新群二维码）。
- 暑期实践出征 / 归来（6-7 月 / 9-10 月）。
- 年终总结 / 星级答辩（5-6 月 / 11-12 月）。
- 跨校 / 跨省大型活动（如对外合作、获奖、媒体报道）。

### 8.2 同步流程

1. **产出审核通过**（本 SOP 第 4 步）后，**额外 1 步**：技术对接负责人（部长 C 轮值）评估是否需要上招新站。
2. 如果需要：
   - 图片丢进 `public/images/<对应目录>/` 覆盖同名文件（命名见 `docs/IMAGE-NAMING-PLAN-CN.md`）。
   - 链接 / 文案改 `src/config.ts` / `src/content.ts`。
   - 不改组件（`src/components/`），不写新代码。
3. **招新季高峰**（7-9 月）：每周 1 次同步，由技术对接负责人主导，1 周内完成。
4. **其他月份**：每月 1 次同步，与部门例会同步进行。

### 8.3 同步禁区

- 改 `src/App.tsx` 的页面区块顺序（除非新一届部长团集体决定）。
- 改 `src/index.css` 的颜色 / 字体（设计 token 不要动）。
- 在 `main` 以外的分支改招新站（除非有明确技术理由 + 至少 2 部长同意）。
- 招新站下线（这事不归宣传部管，归技术负责人）。

> 完整改图规范见 `docs/宣传部/README.md` §3。**我们不是技术部门，但我们要懂"动哪里不破坏"**。

## 9. 自检清单（每周部长会议过一遍）

- [ ] 本周所有接活都已登记
- [ ] 所有方案都已过审（无"口头答应"）
- [ ] 所有中间稿都已 Review（无"已经发了我就发了"）
- [ ] 所有发布都已 Review（无"截止太赶了直接发"）
- [ ] 所有已发布都已归档（无"先发吧回头再整理"）
- [ ] 本周有翻车 / 优秀 → 翻车记录 / 优秀案例 已更新
- [ ] 招新站同步工作已完成本周应同步的部分

## 10. 一句话总结

> **宣传部的产出 = 社团的门面。** 一次好的产出 = 30 个人花一周时间做出来的；一次翻车 = 30 个人花一周时间擦屁股。
>
> **流程不是束缚，是让我们 30 个人都能交付 "我们能拿出去见人" 的东西。**
>
> 工具会变，平台会变，**这套流程的"接 → 做 → 审 → 发 → 归档"五步不会变**。
