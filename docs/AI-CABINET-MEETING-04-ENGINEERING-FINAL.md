## 2. 升级后的五位成员发言

### 2.1 架构工程师｜“避免最后一轮大重构”

- 当前内容、配置、组件已分离；`content.ts` / `config.ts` 是正确的单一编辑入口。
- `vite-plugin-singlefile` 是当前 Cloudflare 静态部署策略的一部分，最后阶段不宜为了“理论上的代码分割”引入可能改变产物和预览行为的动态路由。
- 支持做低风险硬化：交互语义、可复制群号状态、可点击导览、FAQ 关系、构建检查。
- 反对重写整个设计系统、引入状态管理库、地图、埋点、后端或第六版 Hero。

### 2.2 可访问性工程师｜“漂亮不等于可操作”

- `div role=button` 虽有键盘事件，但原生 `button` 已提供正确语义、键盘和焦点行为，应该替换。
- FAQ 应补 `aria-controls`，让辅助技术理解“该按钮控制哪个区域”。
- “已复制”不应只视觉变化，应有 `aria-live` 状态文字。
- 触控元素已多数达到 44px；最终真机检查应确认固定报名条、回顶按钮、导航菜单没有遮挡。

### 2.3 性能工程师｜“最大风险是素材与真实网络，不是 React 本身”

- 正式构建 gzip 约 166KB，脚本不是当前最危险的瓶颈；真实图片库约 26MB，首屏图片和外部字体更值得关注。
- 已有首屏 `preload`、非首屏 `lazy`、`decoding=async`，基础正确。
- 最终素材接入必须补：主视觉尺寸/格式审核、移动网络检查、LCP 测试；没有真实图片时不可假称已完成。
- 不建议在招新前临时引入大型第三方脚本、聊天组件或统计 SDK。

### 2.4 产品工程师｜“导览要能行动，而非只是说明”

- “想陪伴孩子/长者/公共空间”是好方向，但静态三卡只告诉新生答案，不能把他带到相关部门。
- 应点击后自动切到项目部门、强调匹配卡，并给一句“已为你优先标出”提示；不隐藏其他部门，避免误导新生只能选这些。
- CTA 的群号直接展示已经改进；复制反馈应明确，失败时也应保持可手动复制。

### 2.5 测试工程师｜“通过构建不是通过体验”

- 必须把 `typecheck + build + diff --check` 保留为每轮基线。
- 本环境无 Playwright、Puppeteer 和 Chrome，不能声称截图/交互自动化通过。
- 最后交付必须区分：**已验证（构建/类型/静态代码）**与**待真机验证（微信、QQ、iOS、Android、二维码、报名跳转）**。

## 3. 会议四裁决

### 批准立即执行

1. 用原生 `button` 重写二维码翻转交互；
2. 给 QQ 群复制结果添加屏幕阅读器可读状态和失败降级；
3. 为 FAQ 添加按钮和内容区域的关联；
4. 将“按服务对象找方向”卡做成可点击推荐入口，切换项目 Tab 并高亮相应部门；
5. 为高亮状态添加可见、克制的视觉与文字反馈；
6. 完成 `typecheck + build + diff --check`，推送分支，并检查预览 URL 可达性。

### 暂缓，不以“脱胎换骨”为名破坏稳定性

- 重构成多页/后端；
- 新增地图、埋点、聊天机器人；
- 引入大型 UI 框架或状态库；
- 改造 Vite 单文件部署策略；
- 没有真实素材就继续增加视频或图像特效；
- 宣称已完成真机浏览器测试。

## 4. 最终轮验收门槛

### 已可由本环境验证

- TypeScript 无错误；
- Vite 构建成功；
- 无 diff 空白错误；
- 主入口、内部 Hero 预览、部门交互、FAQ、QQ群复制交互在代码层存在合理语义；
- 正常 URL 不出现内部首页选择器。

### 必须由真实设备验证，不能跳过

- iPhone Safari / 微信；
- Android Chrome / 微信 / QQ；
- 375、390、430px 宽度；
- 真实报名表、二维码、群号和外链；
- 真图的授权、裁切、首屏加载与文字对比度；
- 移动端固定 CTA 不遮挡页面底部内容。
