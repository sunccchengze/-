> **性质**：可审计的决策过程记录。  
> **召开原因**：用户要求透明展示“查过什么、检索过什么、各角色如何讨论、如何产生路线”，而不是只展示结论。  
> **召开时间**：2026-08-02 02:45 UTC（北京时间 10:45）。  
> **边界**：本记录呈现可公开验证的证据、工具调用、角色立场、分歧和决定；不呈现模型私有逐字推理草稿。

## 1. 本次会议的问题，不是预设结论

本次要回答的不是“再加什么酷炫功能”，而是：

> 在已有 Hero、项目、部门、荣誉、团队、CTA、FAQ 的基础上，英仔招新站下一步到底应该优先做**视觉扩张**、**真实素材接入**、**报名闭环**、还是**内容/事实核验**？

这是一个优先级决策，因为四件事都值得做，但时间、素材、招新信息和注意力有限。

### 2.3 外部检索（实际检索词与结果）

#### 检索 A

- **查询词**：`大学生 社团 招新 新生 志愿服务 官方 指导 招募 规范`
- **目的**：核验“志愿服务招募”中，规范、培训、记录和服务边界是否值得放在招新体验里。
- **结果中实际参考**：
  - 浙江大学青年志愿者工作细则：强调志愿服务的定义、活动审批/记录、不得把社团内部活动包装为志愿服务等边界；
  - 共青团/教育部相关西部计划材料：强调招募流程、培训、岗位匹配、日常管理服务；
  - 2026 西部计划政策问答：强调审核、培训和服务保障。
- **本项目可迁移的结论**：英仔页面不应使用“刷时长”话术；对儿童、医院、特教等场景应体现培训、匹配、规范和记录，而不是只展示感人瞬间。
- **不直接迁移的部分**：西部计划是国家项目，不等同于校内社团；其选拔与体检流程不能照搬给英仔招新。

#### 检索 B

- **查询词**：`volunteer organization recruitment onboarding best practices student volunteers`
- **目的**：验证招新站是否应把“报名后会发生什么”讲清楚，而不是只有一个报名按钮。
- **结果中实际参考**：
  - Litmos《Best Practices for Volunteer Onboarding》：建议尽快回应报名者、清晰沟通职责/投入与合规要求；
  - Funraise《Nonprofit Volunteer Management Guide 2026》：强调按技能/兴趣匹配角色、培训、明确期望和避免志愿者疲劳；
  - Momentive《Onboard Volunteers: Safety, Compliance & Experience》：强调按风险分级培训、清晰职责、保留培训和参与记录；
  - VolunteerHub《How to Build a Volunteer Onboarding Process That Improves Retention》：强调欢迎、使命连接、30 天触点与反馈。
- **本项目可迁移的结论**：现有“填表—轻松交流—入部启程”的三步加入路径方向正确，但后续需补足实际的欢迎/答复节奏、部门匹配说明和新生第一月体验。
- **不直接迁移的部分**：这些资料多面向非营利组织，不代表中国高校具体制度；只作为体验设计参考，不作为学校政策依据。

## 3. 各角色发言与质询

### 3.1 追问派｜First Principles

**依据**：`App.tsx` 页面顺序、`HeroV3.tsx`、`JoinCTA.tsx`、`docs/QUESTIONS.md`。

- 追问：新生到底是在“选择网页风格”，还是在“判断一个陌生组织是否值得把大学时间交给它”？
- 判断：后者才是核心。V1—V5 的选择只解决第一眼风格，不能替代对项目真实性、团队氛围和加入流程的判断。
- 提议：将网站定义为“信任—共鸣—匹配—行动”的四步页面，而不是年度成果展。
- 对现状的质询：
  1. 首屏有明确名称、五星、成员数和暑期项目，但图片仍是占位/旧图，是否足以建立信任？**否。**
  2. 新生是否能不用理解“启梦/拾辉”就做初步选择？**还不够。**
  3. 报名后下一步是谁联系、多久联系、如何选部门？**页面只给了概括，运营流程未定。**

### 3.2 反对派｜Red Team

**依据**：`IMAGE-SLOTS.md`、`docs/QUESTIONS.md`、`Departments.tsx`、外部检索 A。

- 反对继续优先开发大规模动效、地图或更多首页版本。
- 攻击点一：最终素材与授权没有接入。特别是萤火、病房和儿童场景，图片一旦不当使用，会比“页面不够酷”严重得多。
- 攻击点二：荣誉和数据有已知冲突（玉树届次、立邦等级、B 站统计、讲座场次）；若在大标题中放错，老师与社员会首先失去信任。
- 攻击点三：报名链接、部门链接、日程将于开学前变动；页面再漂亮，入口错误等于转化失败。
- 攻击点四：本次代码检查发现一个真实的 JSX 文本风险，说明“每加一层特效”都可能掩盖基础 QA。
- 要求：把“事实核验、素材授权、链接实测、移动端 QA”设为上线门槛，不设为“以后有空再做”。

### 3.3 机会派｜Opportunity

**依据**：`src/content.ts` 的 2026.7 项目资料、`SummerPractice.tsx`、`IMAGE-SLOTS.md`、外部检索 B。

- 认为不应把收敛理解成变保守。英仔最大机会在于：
  - 玉树第十七届的长期接力；
  - 九峰/彬州双线的具体课堂；
  - 萤火、秦岭、陕博、敬老组成的广阔选择面；
  - 宣传、策划、授课、讲解、陪伴等不同成长技能。
- 机会点一：用实图替换后，夏季实践区能成为“证明今年真的在做”的证据，而不是资料摘要。
- 机会点二：部门区可增加“你想陪伴谁 / 你想练什么”这一层，不增加部门数量，但让新生更容易定位。
- 机会点三：报名页可以承接短视频、海报二维码和公众号推文，形成复用内容资产。
- 条件：故事必须由真实照片、经授权的成员声音和可核验事实支撑；不把服务对象的困难当流量钩子。

### 3.4 外行人｜Beginner Lens

**依据**：`HeroV3.tsx`、`Departments.tsx`、`JoinCTA.tsx`、`FRESHMAN-AUDIT.md`。

模拟问题：

1. “我一进来知道这是公益社，但我不知道我能做什么。”
   - 当前回答：有项目区和部门卡。
   - 不足：品牌名和部门名对新生有认知门槛。
2. “我喜欢拍视频，必须只进宣传部吗？”
   - 当前回答：宣传部可同时跟项目部门，但入口分散在部门文字和 FAQ。
   - 改进方向：在部门区增加更直观的“服务对象 × 成长技能”导览。
3. “我报完名会不会被拉去做不喜欢的事？每周要花多久？”
   - 当前回答：FAQ 中有 2—4 小时、轻松交流等信息。
   - 不足：需要在 CTA 前更早出现一个简短承诺，例如“先了解方向，再选择部门；活动与时间安排会提前说明”。
4. “这些照片真实吗？儿童为什么被拍到？”
   - 当前回答：没有页面级说明。
   - 改进方向：不做冗长声明，但素材选择与图注要体现尊重、必要时只用手部/背影/集体远景。

### 3.5 执行派｜Operator

**依据**：全部本地文件检查、两个检索、当前已知未确认项。

将其转译为可执行队列：

| 优先级 | 动作 | 依赖 | 可验证信号 |
|---|---|---|---|
| P0 | 修复发现的 JSX 文本风险并构建 | 无 | `npm run build` 成功，页面不显示调试字符 |
| P0 | 建立“上线事实核验表” | 社团提供最终口径 | 每个数字/奖项/届次/链接都有负责人和来源 |
| P0 | 确认正常访问与内部预览访问分离 | 已完成，需回归验证 | 正式 URL 不出现首页切换器 |
| P1 | 接收首屏、玉树、秦川、萤火、秦岭 5 组优先素材 | 宣传部素材与授权状态 | 图片替换后仍保持移动端对比度、裁切和加载正常 |
| P1 | 部门区增加“服务对象/成长技能”导览 | 文案确认 | 新人能在 10 秒说出自己可能适合的 2 个方向 |
| P1 | 报名路径端到端实测 | 最终报名表/群/日期 | 微信、QQ、手机浏览器均可到达，且知道下一步 |
| P2 | 用授权社员原话替换匿名引言 | 3 位社员授权 | 真实、具体、不涉及敏感服务对象信息 |
| P2 | 视频接入或删除占位 | 可播放视频文件 | 静音、移动端、失败回退均通过 |

## 4. 会议分歧及处理

| 分歧 | 支持方 | 反对方 | 证据与裁决 |
|---|---|---|---|
| 是否继续做更多 Hero 版本 | 机会派：多版本有助寻找风格 | 反对派：继续发散会拖延正式化 | 保留已有 5 版供内部选择；冻结新增第 6 版。 |
| 是否优先加入更多交互/地图/数据模块 | 机会派：增加记忆点 | 追问派、反对派：不是当前转化瓶颈 | 暂不做；先解决素材、事实、报名闭环。 |
| 是否突出志愿时长 | 新生可能在意 | 指导老师/反对派担忧功利化 | 保留“活动丰富、认真记录、长期陪伴”，不写综测、刷时长或承诺性收益。 |
| 是否用儿童/病房强情绪素材增加传播力 | 可能带来情感冲击 | 伦理、隐私和长期品牌风险 | 不以脆弱处境作为卖点；素材优先选择平等互动、手部、背影或授权集体场景。 |
