# AI 内阁会议三｜移动端优先审计

> **论题**：英仔招新站是否能在移动端和电脑端都有好体验？鉴于大多数新生会扫码进入，如何让移动端优先于桌面端？  
> **会议时间**：2026-08-02 02:59—03:02 UTC（北京时间 10:59—11:02）。  
> **结论前提**：本环境没有 Playwright、Puppeteer 或 Chromium，因此本会议不把“代码静态审计”伪称为“真机验收”。已完成的是：代码/断点审计、构建与 TypeScript 检查；**真实 iOS/Android/微信/QQ 浏览器测试仍是上线门槛。**

---

## 1. 会议三的验收定义

移动端优先不是“电脑端缩小后不报错”，而是 375—430px 宽的扫码用户能完成以下任务：

1. 不横向滚动、不眯眼、不被导航或浮层遮挡；
2. 首屏立刻看懂英仔是什么，并能看到主报名入口；
3. 单手可点：按钮最小 44px、间距足够、核心入口靠近拇指可达区域；
4. 在长页中随时能重新找到报名动作，但悬浮条不遮二维码、页脚或正文；
5. 阅读长卡片时有清楚的层级，不像把桌面海报压缩到手机；
6. 微信里打开时，图片/字体/动效失败也不妨碍读内容和报名。

桌面端标准不是被放弃，而是承担“更丰富比较、横向布局、细读资料”的角色；移动端承担“第一次接触与转化”的主角色。

## 3. 静态证据：当前已具备的移动端基础

| 项目 | 代码证据 | 判断 |
|---|---|---|
| viewport | `index.html` 有标准 viewport | 通过基础项。 |
| 最小页面宽度 | `body { min-width: 320px; }` | 可防极窄设备崩坏，但不代表 320px 已真机验证。 |
| 容器留白 | 767px 以下 `.section-container` 由 48px 总留白降为 32px | 合理，阅读宽度优于直接沿用桌面边距。 |
| 区块节奏 | 767px 以下 `.section-block` 从 160px 降至 72px | 避免手机出现过多空白。 |
| 触控目标 | 主按钮、菜单、轮播点多数有 `min-height: 44px` 或 44px 高度 | 符合基础触控目标。 |
| 固定 CTA | `FloatingChrome` 在用户滚过约 0.65 屏后出现，移动端横向铺满 | 长页中可重新找到报名入口。 |
| 页脚避让 | 移动端 footer 为固定底栏预留额外底部空间 | 降低 CTA 遮挡页脚二维码风险。 |
| 动效降级 | `prefers-reduced-motion` 下全局缩短/取消动画 | 对低性能设备和动效敏感用户较友好。 |
| 移动菜单 | `<lg` 显示菜单；`md` 起保留报名按钮 | 入口不依赖横向桌面导航。 |
| 内容栅格 | 大部分卡片在默认状态为单列，`md` 才转多列 | 方向正确。 |

## 4. 移动端缺陷、讨论与整改

### 缺陷 M-01｜正式 V3 首屏手机正文宽度过窄（已修）

- **代码证据**：原 `HeroV3` 左侧使用 `px-12`，该类在 375px 设备上也生效，内容区仅约 279px；对 48px 级中文标题和招新时间说明过窄。
- **新生视角**：扫完码看到的是大标题与很多换行，容易觉得“像电脑页硬压进手机”。
- **设计师视角**：真正的移动优先不是缩字体，而是先把左右安全边距恢复到 24px 左右。
- **执行裁决**：改为 `px-6`，`sm:px-8`，仅 `lg` 才使用大屏 `px-16`；并增加 `pt-28` 避开固定顶部导航。
- **状态**：已修。

### 缺陷 M-02｜V3 右图浮卡仍沿用桌面 40px 边距（已修）

- **代码证据**：原为 `bottom-10 left-10 right-10 p-6`，手机也使用 40px 边距，压缩了图片与卡片有效空间。
- **反对派观点**：如果主视觉只是为了放一张图却占半屏，手机用户应至少得到清楚、贴边合理的项目摘要。
- **执行裁决**：手机改为 16px 边距/20px padding，`sm`、`md` 逐级恢复更宽边距；图片卡不再浪费可读宽度。
- **状态**：已修。

### 缺陷 M-03｜内部候选 Hero 使 typecheck 失败（已修）

- **代码证据**：`npm run typecheck` 报 `HeroV2.tsx` 未使用 `IMG_LOGO`、`brand`。
- **工程师观点**：即使候选只出现在 `?preview=hero`，它仍被导入和编译；“电脑能看正式 V3”不能成为类型错误的借口。
- **执行裁决**：清理无用导入；后续 5 个候选必须一并通过 typecheck，或迁出正式构建。
- **状态**：已修。

### 缺陷 M-04｜QQ群入口需要翻转，移动端多一步

- **代码证据**：`JoinCTA.tsx` 和 `FlippingQRBlock.tsx` 都要求点击/翻转才出现 QQ 群号。
- **机会派观点**：翻转动作有记忆点，适合视觉展示。
- **新生/执行派反驳**：扫描网页的关键动作是“马上入群”；隐藏群号会增加一次理解和操作。部分用户也不会意识到卡片可点。
- **裁决**：保留翻转作为视觉效果可以，但在 CTA 文案或按钮附近增加**直接可见且可复制的群号**，不能只把它藏在翻面。
- **状态**：待下一轮实现，需要确认是否以“招新 QQ 群：712079220”直接显示在主 CTA 下方。

### 缺陷 M-05｜内部预览器的手机遮挡风险

- **代码证据**：`HeroPreview.tsx` 在手机端使用固定底部横向选择器，最大高度 42vh。
- **判断**：它不在正式 URL 中，因此不是新生正式体验问题；但你用手机挑选 5 版时可能遮住首屏底部。
- **裁决**：优先级低。若继续使用手机预览，切换器应可最小化/关闭，或改为顶部抽屉。
- **状态**：内部工具优化，非正式页阻塞项。

### 缺陷 M-06｜长页“内容堆栈”对手机的认知疲劳

- **代码证据**：`App.tsx` 有十余个连续模块；统计、暑期、荣誉、部门的卡片均含丰富正文。
- **新生视角**：不是每个用户都要看完年报；手机读到后半段时，最容易失去“我下一步该做什么”的方向。
- **设计师观点**：手机端应更早让用户自选路径，而不是强制线性阅读。
- **裁决**：下一轮引入“找方向”轻导航或项目选择入口；压缩主卡默认内容，详情改展开；保留固定 CTA。
- **状态**：会议二、三共同确认的 P1 改造项。

### 缺陷 M-07｜真实设备证据缺失（未解决）

- **事实**：本环境没有可用浏览器自动化，无法证明微信、QQ、Safari、Android WebView 的实际表现。
- **裁决**：任何“移动端已完美”的说法都不成立。上线前必须由真实设备完成以下测试：
  - iPhone Safari/微信；
  - Android Chrome/微信/QQ；
  - 375、390、430px 宽度；
  - 慢网下首屏、二维码、报名表跳转；
  - 字体加载失败、图片加载慢、减少动态效果。
- **状态**：待真实设备。

## 5. 五角色会议记录

### 追问派｜First Principles

- 追问：新生扫码后只有几十秒，最重要的任务是什么？
- 回答：不是浏览所有内容，而是建立安全感、找到感兴趣方向、完成入群或报名。
- 因此：移动端设计应该把“报名/咨询”设计为持续可见的安全出口，把“荣誉/全部资料”设计为按需深入的证据层。

### 反对派｜Red Team

- 质疑：“响应式 class 很多”不代表移动体验好。真正风险是 V3 的宽度、浮卡、隐藏群号、长页疲劳、微信内置浏览器和真实网络。
- 反对在真机测试前宣称移动端优于桌面端。
- 要求：将真实设备截图和端到端报名测试列为上线阻塞条件。

### 机会派｜Blue Team

- 手机扫码是英仔的优势：现场海报/摆摊、公众号推送、短视频都自然导向手机页面。
- 建议把手机页做成“微型招新导览”：首屏立即报名 → 今年正在发生 → 我适合哪个方向 → 直接群号/报名 → 常见顾虑。
- 不建议把手机页变成电脑页的缩小版，也不建议做独立两套内容；应共享事实数据，改变层级与展开方式。

### 外行人｜新生模拟

- “我还没有决定，但不想错过。”——需要清楚的“先加群问问”入口和直接群号。
- “我屏幕小，不会看那么多。”——需要先看到四五个核心事实，不是四层数字卡。
- “我不懂前卫/洩湖。”——需要先按陪伴对象或兴趣筛选。
- “我怕报了就很忙。”——需在 CTA 附近再次说明时间投入和先交流再选部门。

### 执行派｜Operator

移动端改造排序：

1. 已完成：修首屏横向留白、浮卡边距、候选组件 typecheck；
2. 下一步：在 CTA/群卡提供直接可复制的群号，保留二维码/翻转作为辅助；
3. 下一步：用移动优先内容层级压缩统计和暑期卡；
4. 上线前：提交真实设备截图 QA 与报名链路测试记录；
5. 最后：再微调桌面端横向布局，而不是反过来。

## 6. 主席裁决

- **裁决 1**：移动端是正式设计基线，桌面端是其扩展，不是反过来。
- **裁决 2**：当前代码具有不错的移动基础，但尚不能称“移动端比电脑端更好”；真机证据缺失，且仍有群号入口和长页层级问题。
- **裁决 3**：V3 可继续作为正式候选，因为它比满屏轮播更容易在手机上压缩成“文字 → 图片 → 项目摘要”；已对其手机留白与浮卡作首轮修正。
- **裁决 4**：不新增移动端炫技；先让核心路径更短、更直接、更可测。
- **上线门槛**：`typecheck`、`build`、375/390/430 真机截图、微信/QQ 报名跳转、二维码可扫、固定 CTA 不遮挡，必须同时通过。
